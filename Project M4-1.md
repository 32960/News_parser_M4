# Project M4. AINEWS — AI-генератор постов для Telegram

## Задача

Вы разрабатываете сервис для редактора новостного Telegram-канала. Редактор выбирает источники, а сервис собирает
новости, готовит короткие посты с помощью ИИ и публикует их по расписанию.
Через API можно управлять источниками, смотреть результаты и запускать обработку вручную.

**Срок — 2 недели, 4 вебинара.** К сдаче должна работать вся цепочка: **источник → новость → генерация → очередь готовых
постов → Telegram-канал**.

Обязательный минимум — один поддерживаемый сайт, один публичный Telegram-канал в качестве источника и один канал для
публикации. Сайты и тему канала выберите сами.

## Что должен уметь сервис

### Управление источниками

У источника есть название, тип (`site` или `telegram`), адрес и признак активности `enabled`. Через API редактор может
добавить источник, посмотреть и изменить его настройки, включить или отключить сбор.

Для каждого поддерживаемого сайта нужен свой парсер. API принимает только адреса, с которыми эти парсеры умеют работать;
неподдерживаемый адрес отклоняется с понятной ошибкой.
Добавление поддержки нового сайта требует изменения кода. Для Telegram используется общий парсер: новый публичный канал
подключается по username или ссылке `https://t.me/<username>` через API.

Отключённый источник не участвует в сборе и новой генерации. Перед обращением к ИИ сервис ещё раз проверяет, включён ли
источник. Уже собранные новости сохраняются, а готовые посты продолжают публиковаться.
Удалить источник можно только до появления связанных новостей; после этого его можно отключить.

### Сбор новостей и защита от дублей

Сервис собирает новости из включённых источников каждые 30 минут. Тот же сбор можно запустить вручную через API.

Для каждой новости сохраняются источник, заголовок, исходный текст и время сбора. Текст с сайта очищается от HTML; для
Telegram берётся текст сообщения или подпись к медиа.
Если заголовка нет, используйте начало текста. Материалы без текста пропускайте. Для сайта обязательна абсолютная ссылка
на статью; время публикации и сводка сохраняются, если их предоставил источник.

Повторный сбор не должен создавать одинаковые новости и снова тратить запросы к ИИ:

- Для сайта дубль определяется по полному URL статьи, включая параметры запроса.
- Для Telegram — по паре «числовой ID канала + ID сообщения».
- По одному адресу или паре ID сохраняется первая найденная версия. Одинаковый текст с другими адресами или ID считается
  отдельной новостью.

Проверяйте дубли по всей сохранённой истории. Уникальность должна обеспечиваться в БД, в том числе после перезапуска и
при одновременном сборе.

### Генерация постов

Для каждой новой новости включённого источника сервис автоматически запрашивает текст у AI-модели через публичный API. В
запрос передаётся сводка из источника, если она непустая, иначе — исходный текст.

Подготовьте промпт для короткого, понятного поста в Telegram: передать суть новости, не добавлять выдуманные факты,
уместно использовать emoji и приглашение к обсуждению.
Конкретную модель и формулировку промпта выберите сами.

Успешный результат сохраняется и попадает в очередь публикации. Редактор также может запросить генерацию по ID
сохранённой новости.
Каждый такой запрос создаёт новый пост — это позволяет получить другой вариант или повторить попытку после ошибки.
Для отключённого источника ручная генерация недоступна.

### Публикация в Telegram

Сбор и публикация работают по отдельным расписаниям. В **HH:00 и HH:30 по UTC** сервис отправляет в целевой канал один
пост со статусом `generated` через **Telethon**.
Первым выбирается пост с самым ранним временем готовности; при совпадении времени — с меньшим ID. Если очередь пуста,
отправлять ничего не нужно.

После отправки сохраняются статус и фактическое время публикации. Через API можно опубликовать готовый пост сразу или
повторить отправку после ошибки, используя сохранённый текст.
Повторный запрос для уже опубликованного поста возвращает его результат без новой отправки. Пост без готового текста
публиковать нельзя.

Для учебной версии достаточно проверки сохранённого статуса перед отправкой. Защита от дубля при аварийном завершении
между отправкой в Telegram и записью результата в БД — дополнительная задача.

### Ошибки и наблюдение за работой

Через API должны быть доступны собранные новости, список постов и отдельный пост с текстом и текущим статусом. Ошибки
сбора, обращения к ИИ и отправки записываются в логи с указанием источника или поста.
Сбой одного источника не должен останавливать обработку остальных.

При ошибке генерации или публикации пост получает соответствующий статус. Ошибка отправки не удаляет готовый текст: его
можно отправить повторно. Автоматические повторные попытки — по желанию.

## Технические требования

- **FastAPI** — API и Swagger UI по адресу `/docs`. Достаточно локального запуска без авторизации и отдельного
  веб-интерфейса.
- **Celery**, **Redis или RabbitMQ**, **Celery Beat** — фоновые задачи и расписания. Сбор, генерация и отправка
  выполняются в Celery; API возвращает ответ после постановки задачи, не ожидая внешних сервисов.
- **Постоянная БД**, общая для API и фоновых задач. Источники, новости, готовые посты и история публикаций сохраняются
  после перезапуска. Рекомендуется PostgreSQL; допустима другая БД с выполнением требований к связям и уникальности.
- **Telethon** — чтение каналов и публикация через один пользовательский аккаунт. Он должен иметь доступ к источникам и
  право публиковать в целевом канале. Первичная авторизация выполняется отдельно, сессия сохраняется. При
  недействительной сессии фоновая задача сообщает об ошибке, а не запрашивает код входа. Одну сессию нельзя одновременно
  использовать несколькими клиентами.
- Ключи API, параметры подключения и настройки Telegram передаются через окружение. В репозитории нужны `.env.example` и
  `.gitignore`; секреты, локальный `.env` и файлы сессии в Git не попадают.

Структуру модулей, ORM и библиотеки для парсинга выберите сами. Разделите код API, парсеров, генерации и публикации так,
чтобы новый источник или AI-провайдер можно было добавить без переписывания всего сервиса.

### Данные и состояния поста

Ниже — обязательные поля и ограничения. Типы указаны для PostgreSQL; в другой БД используйте эквиваленты. `NULL`
означает отсутствие значения. Все даты хранятся в UTC с учётом часового пояса.
Дополнительные поля можно добавлять по необходимости.

**Источник — `Source`**

| Поле      | Тип                 | Ограничения и назначение                                                                                  |
|-----------|---------------------|-----------------------------------------------------------------------------------------------------------|
| `id`      | `uuid` или `bigint` | Первичный ключ, `NOT NULL`                                                                                |
| `type`    | `text` или `enum`   | `NOT NULL`; только `site` или `telegram`                                                                  |
| `name`    | `text`              | `NOT NULL`, непустое название                                                                             |
| `url`     | `text`              | `NOT NULL`; для сайта — поддерживаемый адрес сбора, для Telegram — публичный username или ссылка на канал |
| `enabled` | `boolean`           | `NOT NULL`, по умолчанию `true`; участвует ли источник в сборе и генерации                                |

**Новость — `NewsItem`**

| Поле                  | Тип                        | Ограничения и назначение                                                                                                    |
|-----------------------|----------------------------|-----------------------------------------------------------------------------------------------------------------------------|
| `id`                  | `uuid`                     | Первичный ключ, `NOT NULL`                                                                                                  |
| `source_id`           | Как у `Source.id`          | `NOT NULL`, внешний ключ на `Source.id`                                                                                     |
| `title`               | `text`                     | `NOT NULL`, непустой заголовок; если его нет — первые 200 символов первой непустой строки `raw_text`, без пробелов по краям |
| `raw_text`            | `text`                     | `NOT NULL`, непустой исходный текст; для сайта — без HTML                                                                   |
| `url`                 | `text`                     | Для сайта обязателен абсолютный URL статьи; для Telegram — ссылка на сообщение, если доступна, иначе `NULL`                 |
| `telegram_channel_id` | `bigint`                   | Числовой ID канала, обязателен для Telegram; для сайта — `NULL`                                                             |
| `telegram_message_id` | `bigint`                   | ID сообщения внутри канала, обязателен для Telegram; для сайта — `NULL`                                                     |
| `summary`             | `text`                     | Сводка от источника; если отсутствует или пуста — `NULL`                                                                    |
| `collected_at`        | `timestamp with time zone` | `NOT NULL`, время сбора новости сервисом                                                                                    |
| `published_at`        | `timestamp with time zone` | Время публикации в источнике; если неизвестно — `NULL`, не подменять временем сбора                                         |

**Пост — `Post`**

| Поле             | Тип                        | Ограничения и назначение                                                             |
|------------------|----------------------------|--------------------------------------------------------------------------------------|
| `id`             | `uuid` или `bigint`        | Первичный ключ, `NOT NULL`                                                           |
| `news_item_id`   | `uuid`                     | `NOT NULL`, внешний ключ на `NewsItem.id`; одна новость может иметь несколько постов |
| `generated_text` | `text`                     | До успешной генерации — `NULL`, после — непустой текст                               |
| `status`         | `text` или `enum`          | `NOT NULL`, по умолчанию `new`; только пять состояний из таблицы ниже                |
| `generated_at`   | `timestamp with time zone` | Время успешной генерации и постановки в очередь; до генерации — `NULL`               |
| `published_at`   | `timestamp with time zone` | Фактическое время отправки в Telegram; до успешной отправки — `NULL`                 |

**Ограничения и связи:**

- Первичные и внешние ключи, `NOT NULL`, допустимые значения `type` и `status`, а также уникальность новостей
  обеспечиваются на уровне БД.
- Для новостей с сайтов уникален `url`; для Telegram — пара (`telegram_channel_id`, `telegram_message_id`). Каждый ID
  сообщения уникален только внутри своего канала.
- Нельзя удалить источник со связанными новостями или новость со связанными постами. Используйте запрет удаления по
  внешнему ключу (`RESTRICT` или эквивалент).
- Условия заполнения полей по типу источника и непустые тексты проверяются при сохранении. У `new` и `generation_failed`
  текст и обе даты поста равны `NULL`; у `generated` и `publication_failed` текст и время генерации заполнены, время
  публикации равно `NULL`; у `published` заполнены все три поля.

| Статус поста         | Значение                                     |
|----------------------|----------------------------------------------|
| `new`                | Запись создана, генерация ещё не завершена   |
| `generated`          | Текст готов и ожидает публикации             |
| `published`          | Пост отправлен в канал                       |
| `generation_failed`  | Не удалось получить текст от ИИ              |
| `publication_failed` | Текст готов, но отправка завершилась ошибкой |

Обычный путь поста: `new → generated → published`. Текст и время генерации заполняются после успешной генерации, время
публикации — после успешной отправки.
Повторная отправка переводит `publication_failed` в `published`; ручная повторная генерация создаёт отдельный пост.

## API

Swagger должен описывать параметры, ответы и ошибки всех перечисленных операций.

| Метод и адрес                   | Назначение                                                                |
|---------------------------------|---------------------------------------------------------------------------|
| `GET /api/sources/`             | Список источников                                                         |
| `POST /api/sources/`            | Добавить источник: `type`, `name`, `url`, `enabled`                       |
| `GET /api/sources/{id}/`        | Посмотреть источник                                                       |
| `PATCH /api/sources/{id}/`      | Изменить источник, в том числе включить или отключить                     |
| `DELETE /api/sources/{id}/`     | Удалить источник без связанных новостей                                   |
| `GET /api/news/`                | Посмотреть собранные новости                                              |
| `GET /api/posts/`               | Посмотреть посты и их статусы                                             |
| `GET /api/posts/{id}/`          | Получить текст и состояние поста                                          |
| `POST /api/parse/`              | Запустить сбор из всех включённых источников; без тела запроса            |
| `POST /api/generate/`           | Создать пост по новости; тело: `{"news_id": "..."}`                       |
| `POST /api/posts/{id}/publish/` | Отправить готовый пост или повторить неудачную отправку; без тела запроса |

Запуск сбора возвращает `202` и `task_id`, запуск генерации или отправки — `202` и `post_id`. Результаты доступны в
списке новостей и карточке поста.
Поле запроса `news_id` указывает на новость, с которой новый пост связан через `news_item_id`.

Для чтения и изменения используйте `200`, для создания источника — `201`, для удаления — `204`. Неизвестный ID даёт
`404`, неверные входные данные или неподдерживаемый сайт — `422`.
Удаление источника с новостями, генерация для отключённого источника и отправка поста без готового текста дают `409`.
Повторная публикация уже отправленного поста возвращает `200` с сохранённым результатом.

Максимум — **100 баллов**. Баллы начисляются за работающие возможности, которые можно проверить через API, в БД и в
Telegram. Каждый критерий ниже оценивается отдельно: **10 баллов** — выполнен полностью, **5** — работает частично, **0
** — отсутствует или не работает. При частичной оценке преподаватель указывает, чего не хватает.

| Сбор из Telegram  | Общий парсер читает сообщения; другой публичный канал можно подключить через API                            |      10 |
| Источники         | Добавление, изменение, включение, отключение и удаление работают по описанным правилам                      |      10 |
| Хранение и дубли  | Связи и данные сохраняются после перезапуска; повторный и одновременный сбор не создают дубли               |      10 |
| AI-генерация      | Автоматическая и ручная генерация работают через реальный AI API; результат сохраняется                     |      10 |
| Публикация        | По расписанию отправляется один пост в нужном порядке; ручная отправка и проверка статуса работают          |      10 |

| API и Swagger     | Все обязательные операции доступны, ответы и ошибки соответствуют ТЗ, документации достаточно для работы    |      10 |

| **Итого**         |                                                                                                             | **100** |

**Бонусные баллы** можно получить за реализацию дополнительной функциональности:

- **Отбор новостей:** фильтры по ключевым словам, языку и давности публикации, чтобы в канал попадали свежие материалы
  по выбранной теме.
- **Новые источники:** дополнительные парсеры сайтов и подключение RSS-лент через API.
- **Поиск похожих новостей:** распознавание одного события в разных источниках, даже если ссылки и формулировки
  отличаются.
- **Редакторская проверка:** просмотр и редактирование черновика, одобрение или отклонение поста. В этом режиме
  публикация возможна только после одобрения.
- **Управление очередью:** изменение порядка постов, отмена запланированной отправки и выбор времени публикации с учётом
  часового пояса.
- **Настройки стиля:** выбор длины, тона и языка постов, сохранение собственных промптов без изменения кода.
- **Контроль расходов на ИИ:** учёт запросов и использованных токенов, лимит на день и приостановка генерации при его
  достижении.
- **Восстановление после сбоев:** автоматические повторные попытки с задержкой и ограничением их числа, уведомление
  редактора, если обработка так и не завершилась.
- **Статистика работы:** число собранных, сгенерированных и опубликованных материалов, ошибки и время последнего
  успешного сбора по каждому источнику.
- **Защита управления:** авторизация в API и разграничение прав редактора и администратора.
- **Тесты основных сценариев:** проверка дублей, отключения источников, ошибок внешних сервисов и повторной отправки без
  обращения к реальным платным API.

Эти возможности необязательны. Бонусные баллы определяет ментор с учётом пользы функции и качества её реализации.
